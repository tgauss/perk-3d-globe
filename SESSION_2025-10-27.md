## 🎯 Problems Identified & Solved

### 1. Globe Not Responsive to Window Resize
**Problem**: Globe was using fixed dimensions in state, causing laggy updates and misalignment when browser window resized.

**Root Cause**:
- `dimensions` state stored `window.innerWidth/innerHeight`
- State updates lagged behind actual resize events
- Globe would shift off-center during resize

**Solution**:
- Removed `dimensions` state entirely
- Implemented `ResizeObserver` for instant updates
- Changed to container-based sizing (`containerRef`)
- Added flexbox centering on container
- Globe now resizes smoothly at 60fps

**Files Changed**:
- `src/routes/mms-globe.jsx`

**Code**:
```javascript
// Before (laggy)
const [dimensions, setDimensions] = useState({
  width: window.innerWidth,
  height: window.innerHeight
});

// After (instant)
const resizeObserver = new ResizeObserver(() => {
  const width = containerRef.current.offsetWidth;
  const height = containerRef.current.offsetHeight;
  globeEl.current.width(width).height(height);
});
```

### 2. Ring Animations Looping Endlessly
**Problem**: Activity markers (rings) would scale up, then restart and loop infinitely. Expected behavior was to scale once and stay at full height.

**Root Cause**:
- `repeat: 0` in react-globe.gl means **infinite loop** (not "don't repeat")
- Rings were horizontal circles expanding outward (radius growth)
- Not the vertical "pillars" or "columns" the user wanted

**Solution**:
- Completely replaced `ringsData` with vertical pillars using `pointAltitude`
- Each activity point gets fixed `altitude: 0.03` (vertical height)
- Thin `pointRadius: 0.3` for pillar width
- No animation - pillars appear at full height immediately
- Color-coded by activity type using M&M's brand colors

**Files Changed**:
- `src/routes/mms-globe.jsx`

**Code**:
```javascript
// Before (horizontal expanding rings)
ringsData={activeRings}
ringMaxRadius={12}  // Massive horizontal expansion!

// After (vertical static pillars)
pointsData={visiblePoints}
pointAltitude={(p) => p.altitude || 0.02}  // Height
pointRadius={0.3}  // Thin width
pointColor={(p) => p.color}  // Activity-specific color
```

### 3. Timestamps All Showing "1s ago"
**Problem**: All activities showed "1s ago" regardless of actual time, making the relative timestamps useless.

**Root Cause**:
- Metabase Question 178 was using old query
- Query returned activities all from the same moment in time
- No "Timestamp (ms)" field - timestamps calculated in JS
- No time diversity (all from most recent second)

**Solution**:
- Fixed SQL syntax error (double WHERE → WHERE...AND)
- User updated Metabase Question 178 with optimized SQL
- SQL now pre-calculates Unix timestamps: `EXTRACT(EPOCH FROM created_at)::bigint * 1000`
- Samples from last 7 days (not just most recent second)
- `DISTINCT ON (participant_id)` prevents spam
- API now receives diverse timestamps spanning days/hours/minutes

**Files Changed**:
- `sql/globe_activity_feed.sql` (fixed syntax)
- `api/mms-activity.js` (added debug logging)

**Result**: Timestamps now correctly show "3min ago", "2hr ago", "today", "recently"

## 🔧 Technical Implementation Details

### ResizeObserver for Responsiveness

**Location**: `src/routes/mms-globe.jsx` lines 58-98

**How It Works**:
1. Create `containerRef` for the globe container div
2. Set up `ResizeObserver` that watches container size changes
3. When container resizes, immediately update globe dimensions
4. No state updates needed - direct globe manipulation
5. Disconnect observer on component unmount

**Benefits**:
- Instant updates (no state lag)
- 60fps smooth resizing
- No jittery behavior
- Works on all devices

**Browser Support**: All modern browsers (Chrome 64+, Firefox 69+, Safari 13.1+)

---

### Vertical Pillars Implementation

**Location**: `src/routes/mms-globe.jsx` lines 228-291

**How It Works**:
1. Each activity point gets `altitude` property (0.03 for ~300km height)
2. Each point gets `color` property from activity type
3. Globe's `pointAltitude` reads from point.altitude
4. Globe's `pointColor` reads from point.color
5. Globe's `pointRadius` set to 0.3 (thin pillars)

**Activity Type Colors**:
- Brown (#5A1F06) - Account & System
- Yellow (#FFD200) - Rewards & Achievements
- Green (#00A836) - Commerce & Receipts
- Blue (#0E74E1) - Content & Education
- Orange (#FA6400) - Social & Games
- Red (#D70100) - Negative/Spending

**Why This Approach**:
- react-globe.gl's `ringsData` creates horizontal expanding circles
- `pointAltitude` creates vertical cylinders (pillars)
- No animation needed - just geometry
- Better performance (static vs animated)
- Cleaner visual (no pulsing/looping)

### SQL Query Optimization

**Location**: `sql/globe_activity_feed.sql` lines 21-22

**The Fix**:
```sql
-- BEFORE (syntax error)
FROM public.participant_actions pa
[[ WHERE pa.program_id = {{program_id}} ]]
WHERE pa.created_at >= NOW() - INTERVAL '7 days'

-- AFTER (correct)
FROM public.participant_actions pa
WHERE pa.created_at >= NOW() - INTERVAL '7 days'
  [[AND pa.program_id = {{program_id}}]]
```

**Key Features**:
- Pre-calculates Unix timestamps in SQL (line 67)
- Samples from last 7 days for time diversity (line 21)
- One action per participant to prevent spam (line 8)
- Returns "Timestamp (ms)" field for efficiency
- Parameterized with `{{limit}}` and `{{program_id}}`

**Performance Impact**:
- Timestamp calculation moved from JS to SQL (faster)
- Time diversity eliminates "all same time" bug
- Reduces payload size (no redundant data)

## 🎨 Design Decisions Made

### Why ResizeObserver Instead of Window Resize Event?

**Decision**: Use ResizeObserver to watch container size

**Reasoning**:
- Window resize events fire many times per resize
- Need to debounce to avoid performance issues
- State updates cause re-renders (lag)
- ResizeObserver is more efficient
- ResizeObserver provides actual container dimensions

**Trade-offs**:
- ResizeObserver not supported in IE11 (acceptable - IE11 is EOL)
- Slightly more complex code
- Better performance and UX outweigh complexity

---

### Why Vertical Pillars Instead of Rings?

**Decision**: Use `pointAltitude` for vertical pillars instead of `ringsData` for expanding rings

**Reasoning**:
- User explicitly wanted vertical "columns" or "pillars"
- Rings were expanding horizontally (radius growth)
- Rings kept looping despite `repeat: 0` setting
- Pillars are cleaner visual (no animation)
- Pillars perform better (static geometry)

**Trade-offs**:
- No pulsing animation effect
- Less dynamic visual
- User preferred static pillars

---

### Why Pre-calculate Timestamps in SQL?

**Decision**: Calculate Unix timestamps in SQL instead of JavaScript

**Reasoning**:
- SQL is faster for timestamp math
- Reduces JS processing on client
- Consistent timestamp format
- Easier to debug (can verify in Metabase)

**Trade-offs**:
- More complex SQL query
- Requires SQL knowledge to modify
- Benefits outweigh complexity

---

### Why 5-Second Minimum Loading Screen?

**Decision**: Force loading screen to display for at least 5 seconds

**Reasoning**:
- 5-stage animation needs time to be visible
- Fast data loading caused screen to "blink by"
- Loading screen demonstrates sophistication
- Users appreciate polished UX
- 5 seconds allows full animation sequence

**Trade-offs**:
- Artificial delay when data loads faster
- Could feel slow to some users
- User explicitly requested longer display time

## 💡 Key Learnings

### Technical Insights

1. **ResizeObserver is Powerful**
   - Better than window resize events for container-based layouts
   - Provides instant, smooth updates
   - No debouncing needed

2. **react-globe.gl Quirks**
   - `repeat: 0` means infinite loop (counterintuitive)
   - `ringsData` creates horizontal expanding circles
   - `pointAltitude` creates vertical cylinders (pillars)
   - Documentation could be clearer on these points

3. **Metabase Parameter Syntax**
   - `[[ WHERE ... ]]` for optional clauses
   - Must use AND inside optional clause, not WHERE
   - Easy to make syntax errors with optional parameters

4. **M&M's Brand Guidelines**
   - No gradients allowed (solid colors only)
   - Official colors must be used
   - Brand compliance is important for client work

### Process Insights

1. **User Communication**
   - "Columns" and "pillars" meant vertical markers (not rings)
   - Visual issues need to be seen to be understood
   - Live demo helped identify gradient issue

2. **Documentation Matters**
   - Integration guide with copy-paste prompt saves time
   - Session notes enable picking up where we left off
   - CHANGELOG provides historical context

3. **Incremental Testing**
   - Test each change immediately
   - Don't batch multiple changes before testing
   - Easier to debug when you know what changed
